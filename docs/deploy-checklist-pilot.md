### Rollback plan (decide before deploying)
- **App (front end):** revert the faulty commit on `main` (`git revert <sha>` + push) → GitHub Pages republishes the previous version in about 1 minute. The service worker cache name changes with each release, so phones pick it up on next open.
- **Edge Functions:** redeploy the previous code from the repository history (`supabase/functions/<name>/index.ts` at the previous commit).
- **Database:** migrations are additive (new functions, table, trigger). To stop pushes instantly without a migration: remove the Vault secret `push_hook_secret` (the trigger then sends nothing). To stop sign-ups: Authentication → Sign In / Providers → disable sign-ups.
- **Secret leak:** rotate it at the provider (Brevo, DeepL, VAPID pair, hook secrets), update Supabase secrets, redeploy the function.

## Rollback / stop triggers
- Sign-up or sign-in fails for **2 testers in a row** (after checking spam) → stop, check Auth logs.
- Any person sees another person's private data (birth date, e-mail, phone, a hidden reply, someone outside the venue) → **stop immediately**, revert, investigate.
- A block or report does not take effect → stop the encounter part of the test.
- Repeated 5xx in an Edge Function log → switch the feature off (`providers` flag or Vault secret) and continue the rest.
